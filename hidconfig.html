📋 Copy / Paste

Copy / Paste — carry text between computers

Text stored on the Pi in its own copy_paste/ files. Open this page on the other computer, press 📋 Copy, and paste. Nothing is typed out key-by-key, so length costs a one-off transfer rather than minutes of keystrokes.

Kept apart on purpose: this has its own storage and its own transfer channel, and no part of the remapping engine reads it — so anything wrong with a saved item cannot affect your keys, macros or expansions.

Items are read-only until you press ✎ Edit. Up to 32 KB per item and 128 KB in total; transfer runs at roughly 9 KB/s, so a 30 KB script takes about 3 seconds to save. Text is stored and returned verbatim — no character sequence is interpreted.

    Expansion sets
    
    
    One file per set on the Pi (expansion_sets/).
    Toggle a set's checkbox to (de)activate it; the engine hot-reloads within
    ~2 s of ⬆ Save sets. Regex items support $1–$9 captures,
    {{#…}} inline calculation, {YYYY}-{MM}-{DD} date math and {^} cursor
    placement.
    
    
    
      
      
      
      
    
    
    
    
    
    
      
      
    
    
    
    
    
    
      
      
      
      
    
    
    
    
      List transforms (for turning a typed or captured list into a tidy one):
      {{~SORT(a|c|b)}} sorts, {{~UNIQ(...)}} removes
      duplicates keeping the first of each, {{~SORTU(...)}} does both.
      Items separate on | or a newline. Combine with a regex capture,
      e.g. trigger (.+)/su → {{~SORTU($1)}}.
      
    Note: these cannot read your computer's clipboard. This device is a
      USB keyboard — it can only send keystrokes, and there is no path by which the
      clipboard could travel back to it. Type or paste the list, then trigger.
      

    
      Where edits go: expansion sets are stored in their own files on the Pi
      (expansion_sets/), not in your profile. Editing an item here needs
      ⬆ Save this set (or ⬆ Save sets) — ⬆ Save to device saves the profile and
      will not save expansion changes.

      Duration column
      
    
      Works out how long something took and types it for you. The start time is read
      back out of what you have already typed — 10:50, 1440h,
      930a, 2:30pm — so you can see and correct what is being measured.
      A bare number like 1440 is ignored on purpose: it is usually a year or a
      quantity, not a time.
    
      
    
        
    time + duration
            types the time, then the gap. 10:50- tm  →
            10:50- 11:09 (19m). With nothing to read back it falls back to
            when this trigger last fired.
    
        
    duration only
            types just the gap, for two times you typed yourself.
            1440h-1530h dur  → 1440h-1530h (50m)
    
      
    
      
    
      A + means the other end of the range is not on screen. Ranges that end before
      they start are read as crossing midnight, so 2300h-0100h is 2h.
      Remember ⬆ Save to device.

    📝 Special Notes — save text without leaving the window
    
    
    Wrap something in a note tag and the Pi appends it
    to a Copy / Paste entry as a new line. Type it anywhere — an email, a terminal, a
    dialog box — and it lands in the same place. The closing tag is what fires it.
    
    
    
      
    ;;n;;call Dana;;/n;;
          saves, and leaves what you typed plus a confirmation
    
      
    ;;!n;;call Dana;;/n;;
          saves, then erases the whole thing — for jotting a note anywhere
    
    
    
    
    The ! goes at the front because
    that is when you know whether the note should survive. Both use the same closing tag.
    All of it happens on the Pi — this page does not need to be open.
    
    
    
    
    
    
    Removing a rule here does not delete what it saved — the Copy entry stays exactly
    where it is and becomes an ordinary item, with its Delete button back. These save with the
    top ⬆ Save to device.
    
    
    
      Why ;;n;; and not \\ or ,,,
      
    It has to survive being typed into code without
      ever firing by accident. ,,, is a C# multidimensional array
      (int[,,]) and a JavaScript sparse array; @@ is T-SQL;
      ?? is C#; %% and !! are R; :: is C++
      and R; \\ is a literal backslash in Python and R strings and the start of a
      Windows UNC path. A semicolon-wrapped tag collides with none of them, and it reads as an
      open/close pair, so another note type is just another letter.

    Scroll acceleration (layer 0 wheel): momentum v = v·0.98^dt_ms + detents,
  output v + 0.82·(1.4v)³, clamped ±150, slow-scroll halved below 3.1 and again below 2.0,

    Unicode typing method (how ☑ / Δ are typed)
    
    
    
    
    
      ❓ Which method should I pick?
      
    
        Characters with no key on your layout (☑, Δ, →) have to be typed as a
        numeric escape. Windows has two, and no single one works everywhere —
        pick the one matching where you type most.
        
    
          
    MethodSendsWorks inFails in
    
          
    
              win_auto (default)
              Alt+0NNN when the character is CP1252, hex otherwise
              Everywhere, for every accented Latin letter, the Euro,
                  curly quotes and dashes. Numpad digits only, so it can
                  never trigger a menu accelerator, and it needs no registry
                  change.
              Nothing, within CP1252. Beyond it (☑, emoji) it falls back
                  to win_alt_hex and inherits that row's caveat.
    
          
    win_alt_hexAlt + numpad + then hex (2611)
              Browsers, Teams, Start menu, most apps
              Office — it ignores the “+” and reads the digits as
                  decimal, so 2611 becomes U+0A33 ਲ਼.
    
                  Also anywhere EnableHexNumpad is not set —
                  the hex digits a–f are typed as Alt+letter, which Windows
                  then delivers as MENU ACCELERATORS. “ó” is hex f3, so it
                  sends Alt+F and opens the browser menu instead of typing
                  anything.
    
          
    win_alt_decAlt + decimal (9745)
              Office (Word, Outlook, OneNote) — full Unicode
              Browsers — they wrap it to one byte, so 9745 → ◄
    
          
    win_alt_xtypes 2611 then Alt+X
              Office and many editors; no registry setting needed
              Anywhere without Alt+X support (browsers, dialogs)
    
          
    mac_option_hexOption + 4 hex digits
              macOS everywhere
              Needs the “Unicode Hex Input” source enabled and selected
    
          
    linux_ctrl_shift_uCtrl+Shift+U, hex, Space
              GTK / IBus appsQt apps and some terminals
    
        
    
        Rule of thumb: leave it on win_auto. Choose
        win_alt_dec if you are only ever in Office and want
        characters above CP1252; choose win_alt_hex only if you
        have set the EnableHexNumpad registry value and
        logged out and in again. Num Lock must be on for every Alt method.
        
    To enable hex entry (only needed for characters outside CP1252),
        run in an admin PowerShell and then sign out:
    
        reg add "HKCU\Control Panel\Input Method" /v EnableHexNumpad /t REG_SZ /d 1 /f
        Values above U+FFFF are unreliable with every Alt method.
        
    Always reliable alternative: put the character in a
        Copy / Paste item and paste it — no escape sequence involved.
